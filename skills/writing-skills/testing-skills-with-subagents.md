# Testing Skills With Subagents

**Load this reference when:** designing pressure scenarios or baseline/GREEN skill tests for a changed route.

## Idea

Skill testing is RED → GREEN on process docs:

1. **RED** — run a scenario without the new guidance; capture failure/rationalization  
2. **GREEN** — write minimal skill text addressing that failure  
3. **REFACTOR** — close new loopholes; re-check  

## Scope (lean)

Pressure-test **changed** routing, handoff, hierarchy, or completion only.  
Do **not** build one pressure case per active skill or an exhaustive corpus.

## When

- Discipline rules agents want to skip  
- Description/trigger changes  
- New completion criteria or handoffs  

Skip pure reference lookups with no rule to violate.

## Pressure types

Time, sunk cost, authority ("ship now"), exhaustion, "tests after are fine". Combine two when the skill is high-stakes.

## Method

1. Write the temptation scenario (user message + context).  
2. Baseline without skill (or with old text).  
3. Note exact failure.  
4. Edit skill.  
5. Re-run same scenario.  
6. Stop when the changed route holds — do not expand to unrelated skills.

## Success

Agent follows the checkable completion criterion under the tested pressure. No requirement for multi-skill campaigns.
